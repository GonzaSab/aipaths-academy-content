> Explicación estructurada para principiantes sobre las principales formas de trabajar con ChatGPT y la diferencia entre usar recursos locales y servicios en la nube.

**Última revisión: 30 de julio de 2026.**

> **Disponibilidad:** Work, Codex local o remoto, Projects, Scheduled Tasks, aplicaciones y memoria pueden variar según el plan, la región, el dispositivo y las políticas del workspace. Revisa las opciones visibles en tu cuenta antes de diseñar un flujo crítico.

## Mapa general

La forma más sencilla de entender el ecosistema de ChatGPT es separar **cinco conceptos**:

1. **Chat**: conversar, preguntar y pensar contigo.
2. **Work**: ejecutar trabajos más largos y producir entregables terminados.
3. **Codex**: trabajar específicamente con código, repositorios y herramientas de desarrollo.
4. **Projects**: mantener organizado el contexto de un tema o iniciativa.
5. **Scheduled Tasks**: hacer que ChatGPT ejecute algo más adelante, de forma recurrente o cuando cambie una condición.

Después existe una segunda dimensión, independiente de la anterior:

- **Cloud o nube**: el trabajo se ejecuta en infraestructura administrada por OpenAI.
- **Local**: el agente puede acceder, con permiso, a archivos, carpetas, aplicaciones o comandos de tu ordenador.

Esta distinción es fundamental:

> **Chat, Work o Codex indican qué tipo de experiencia utilizas; local o cloud indica dónde están los recursos y dónde se ejecutan las acciones.**

## 1. El modelo mental más importante

Piensa en ChatGPT como una empresa con diferentes trabajadores y herramientas:

| Elemento | Analogía sencilla |
|---|---|
| **Chat** | Un asesor con quien hablas |
| **Work** | Un asistente que recibe un encargo y prepara el resultado |
| **Codex** | Un desarrollador de software |
| **Project** | Una carpeta de trabajo con contexto, documentos e instrucciones |
| **Scheduled Task** | Una alarma o proceso automático |
| **Cloud** | Una oficina remota de OpenAI |
| **Local** | Tu propio escritorio y tu ordenador |

Un **Project** no es un trabajador: es un contenedor.

Una **Scheduled Task** tampoco es un trabajador: es una instrucción para ejecutar algo en otro momento.

**Chat, Work y Codex sí son formas diferentes de interactuar con la inteligencia artificial.**

## 2. Qué es Chat

### Idea básica

**Chat** es la experiencia conversacional normal de ChatGPT. Está pensada para:

- hacer preguntas;
- recibir explicaciones;
- buscar información;
- generar ideas;
- escribir o corregir textos;
- analizar un documento;
- traducir;
- razonar sobre un problema;
- mantener una conversación rápida.

### Cómo trabaja Chat

Normalmente funciona así:

1. Tú escribes un mensaje.
2. ChatGPT responde.
3. Tú corriges, amplías o cambias la dirección.
4. ChatGPT continúa usando el contexto de la conversación.

Es principalmente una dinámica de:

```text
pregunta → respuesta → nueva pregunta → nueva respuesta
```

Aunque Chat puede utilizar herramientas —por ejemplo, búsqueda web, generación de imágenes, archivos o aplicaciones conectadas— el centro de la experiencia sigue siendo la conversación.

### Ejemplos apropiados para Chat

- «Explícame qué es una API».
- «Resume este contrato en lenguaje sencillo».
- «Ayúdame a redactar un correo».
- «Compara estas dos opciones».
- «Busca información reciente sobre este tema».
- «Enséñame Excel desde cero».
- «Analiza estos datos y dime qué significan».

### Cuándo Chat puede quedarse corto

Chat no es necesariamente la mejor opción cuando el encargo exige:

- muchos pasos;
- trabajar durante más tiempo;
- consultar múltiples fuentes;
- manipular varios archivos;
- crear un entregable profesional completo;
- operar sobre tu ordenador;
- ejecutar comandos;
- revisar un proyecto de software entero.

En esos casos aparece **Work** o, cuando el trabajo es programación, **Codex**.

## 3. Qué es Work

### Idea básica

**Work** es un agente para trabajos más largos, complejos y orientados a resultados.

No está pensado solamente para responderte, sino para **tomar un encargo, dividirlo en pasos, utilizar herramientas y producir un resultado terminado**. Puede servir para investigar, analizar información y crear documentos, hojas de cálculo, presentaciones, informes o sitios.

### Diferencia práctica entre Chat y Work

En Chat dices:

> «Explícame cómo debería estructurar una presentación sobre mi negocio».

En Work dices:

> «Analiza estos documentos y crea una presentación de 15 diapositivas para inversores, con gráficos, narrativa, riesgos y conclusiones».

En el primer caso buscas orientación. En el segundo buscas un **producto terminado**.

### Cómo trabaja Work

Un flujo típico puede ser:

1. Entender el objetivo.
2. Revisar los archivos disponibles.
3. Investigar información externa.
4. Organizar un plan.
5. Analizar los datos.
6. Crear el entregable.
7. Validar el resultado.
8. Entregarte el archivo o resultado final.

La diferencia no es solamente que «razone más». Está diseñado para **ejecutar un flujo de trabajo**.

### Ejemplos adecuados para Work

- Preparar un informe de mercado.
- Crear una presentación ejecutiva.
- Construir una hoja de cálculo.
- Analizar múltiples contratos.
- Investigar competidores.
- Convertir notas en un documento profesional.
- Crear un plan de proyecto completo.
- Revisar información de varias fuentes.
- Trabajar con archivos locales, cuando utilizas la aplicación de escritorio y das los permisos correspondientes.

### Work local y Work cloud

**Work no significa automáticamente local.** Puedes utilizar:

- **Work cloud**: ejecuta el trabajo en infraestructura de OpenAI.
- **Work local**: utiliza recursos de tu ordenador cuando la aplicación y los permisos lo permiten.

> Work describe el tipo de agente. Local o cloud describe el entorno donde trabaja.

## 4. Qué es Codex

### Idea básica

**Codex es el agente de programación de OpenAI.** Está especializado en:

- escribir código;
- entender repositorios;
- corregir errores;
- ejecutar pruebas y comandos;
- revisar cambios;
- modificar archivos;
- trabajar con Git;
- preparar implementaciones;
- revisar pull requests;
- ayudar a publicar software.

Puede usarse desde la aplicación de escritorio, una terminal mediante Codex CLI, extensiones de desarrollo y entornos remotos compatibles.

### Diferencia entre Work y Codex

Ambos pueden realizar trabajos largos. La diferencia es su especialización:

| Work | Codex |
|---|---|
| Trabajo general | Desarrollo de software |
| Informes | Repositorios |
| Presentaciones | Código |
| Documentos | Terminal |
| Hojas de cálculo | Tests |
| Investigación | Git |
| Análisis empresarial | Depuración |
| Entregables generales | Cambios de software |

**Ejemplo de Work:**

> «Analiza las ventas y crea una presentación para dirección».

**Ejemplo de Codex:**

> «Abre este repositorio, identifica por qué falla el inicio de sesión, corrige el problema, ejecuta las pruebas y explícame los cambios».

### Codex local

Codex local puede inspeccionar, modificar y ejecutar código dentro del directorio seleccionado:

```text
Tu ordenador
└── Carpeta de proyecto
    ├── src/
    ├── tests/
    ├── package.json
    └── README.md
```

Con los permisos establecidos, puede:

- abrir y editar esos archivos;
- ejecutar `npm test`;
- utilizar un compilador;
- trabajar con Git;
- crear nuevos archivos;
- analizar errores de la terminal.

### Codex remoto o cloud, cuando está disponible

Codex también puede trabajar en entornos remotos administrados. Normalmente:

1. se conecta o copia un repositorio al entorno remoto;
2. prepara un entorno aislado;
3. ejecuta allí el trabajo;
4. produce cambios o un diff;
5. tú revisas esos cambios;
6. después puedes incorporarlos al repositorio.

### Diferencia crítica entre Codex local y cloud

**Codex local** trabaja directamente con:

- tus carpetas;
- tu instalación de Git;
- tus herramientas y dependencias;
- tu terminal;
- tus credenciales locales, según la configuración;
- el estado actual exacto de tu ordenador.

**Codex remoto o cloud, cuando está disponible,** trabaja en:

- un entorno remoto;
- una copia o versión conectada del repositorio;
- dependencias instaladas en ese entorno;
- permisos y red definidos para la tarea;
- infraestructura administrada externamente.

### Cuándo utilizar cada uno

Usa **Codex local** cuando:

- los archivos solo existen en tu PC;
- necesitas programas instalados localmente;
- necesitas comprobar exactamente tu entorno;
- quieres controlar cada cambio en tu repositorio local.

Elige **Codex remoto o cloud, cuando esté disponible,** si:

- quieres delegar una tarea sin mantener tu ordenador ocupado;
- quieres aislar el trabajo;
- quieres ejecutar tareas remotas;
- quieres que varias tareas trabajen sobre problemas diferentes;
- el repositorio está conectado y se puede reproducir correctamente.

## 5. ChatGPT y Codex: no son lo mismo

**ChatGPT** es el producto o plataforma general. Dentro de su ecosistema puedes encontrar:

- Chat;
- Work;
- Projects;
- Scheduled Tasks;
- herramientas;
- aplicaciones conectadas;
- memoria;
- voz.

**Codex** es una experiencia especializada en desarrollo de software, vinculada a tu cuenta o plan, pero con interfaces, historial y flujos propios.

Una formulación útil sería:

> «Uso ChatGPT para trabajar con Chat y Work, y utilizo Codex dentro del mismo ecosistema para programar».

## 6. Local frente a cloud

### Qué significa cloud

Cloud significa que el trabajo se ejecuta en servidores remotos. Tu dispositivo envía el contexto necesario, que puede incluir:

- tus instrucciones;
- archivos adjuntos;
- datos autorizados de aplicaciones conectadas;
- una copia del repositorio necesario.

El servidor realiza el procesamiento y devuelve el resultado.

### Ventajas del cloud

- Funciona desde web o móvil.
- No depende tanto de la potencia de tu ordenador.
- Puede continuar en un entorno remoto.
- Permite sincronización entre dispositivos.
- Puede ejecutar tareas programadas.
- Puede aislar ciertos trabajos.
- Facilita agentes remotos y tareas delegadas.

### Limitaciones del cloud

Un agente cloud no puede entrar mágicamente en tu ordenador. No puede ver:

- todas tus carpetas;
- tu escritorio;
- archivos que no cargaste;
- programas no conectados;
- contraseñas;
- terminales locales;
- discos externos;
- servicios internos de tu red;

salvo que exista una herramienta, conexión o permiso explícito que lo permita.

### Qué significa local

Local significa que una aplicación o agente instalado en tu ordenador puede interactuar con recursos del equipo:

- una carpeta;
- un repositorio;
- una terminal;
- un editor;
- una aplicación;
- determinados archivos;
- una ventana o pantalla, cuando existen permisos apropiados.

### Local no significa «sin internet»

Un agente puede leer archivos y ejecutar herramientas localmente, pero consultar un modelo que funciona en servidores externos.

Por ejemplo, Codex CLI puede operar desde tu terminal mientras las solicitudes al modelo se procesan de forma remota. «Local» describe dónde están las herramientas y dónde se aplican los cambios; no significa necesariamente que el modelo completo funcione sin conexión.

### Tabla comparativa

| Pregunta | Local | Cloud |
|---|---|---|
| ¿Dónde están los archivos principales? | En tu PC | En un entorno remoto o como adjuntos |
| ¿Puede usar tu terminal? | Sí, con permisos | Solo una terminal remota |
| ¿Puede usar programas instalados en tu PC? | Potencialmente sí | No directamente |
| ¿Puede seguir trabajando sin tu PC activo? | Normalmente no | Frecuentemente sí |
| ¿Se sincroniza entre dispositivos? | El trabajo local puede no hacerlo | Normalmente sí |
| ¿Tiene acceso automático a todo tu PC? | No | No |
| ¿Necesita permisos? | Sí | Sí, para fuentes conectadas |
| ¿Está aislado de tu sistema? | Menos | Más |

## 7. Qué se mueve entre local y cloud

Imagina que Codex local revisa:

```text
src/login.ts
```

Para razonar sobre ese archivo, normalmente necesita proporcionar al modelo:

- tu instrucción;
- partes relevantes del código;
- resultados de comandos;
- mensajes de error;
- diferencias entre versiones;
- contexto necesario.

Eso no significa que envíe automáticamente todo tu disco. El alcance depende de la carpeta seleccionada, los permisos, la configuración, las herramientas, tus instrucciones y las políticas aplicables.

Por seguridad:

- autoriza solo las carpetas necesarias;
- revisa los comandos;
- evita incluir secretos;
- maneja los archivos `.env` con cuidado;
- revisa los cambios antes de confirmarlos;
- limita el acceso de red cuando sea posible;
- usa entornos de prueba.

## 8. Qué son Projects

### Idea básica

Un **Project** es un espacio de trabajo que mantiene juntos:

- conversaciones;
- archivos;
- instrucciones;
- contexto;
- recursos relacionados con un mismo objetivo.

### Un Project no ejecuta trabajo por sí mismo

Es una carpeta inteligente. Dentro puedes iniciar Chat, Work u otras herramientas disponibles.

### Ejemplo

```text
Proyecto: Lanzamiento de mi nueva tienda
├── Instrucciones
│   ├── Responder en español
│   ├── Usar tono profesional
│   └── Priorizar clientes de Reino Unido
├── Archivos
│   ├── plan-negocio.pdf
│   ├── precios.xlsx
│   ├── investigacion.docx
│   └── logo.png
└── Chats
    ├── Estrategia de lanzamiento
    ├── Análisis de competidores
    ├── Calendario de contenidos
    └── Presentación para inversores
```

### Para qué sirve

Projects es útil cuando:

- el trabajo dura semanas o meses;
- tienes varios chats sobre el mismo tema;
- necesitas reutilizar documentos;
- quieres instrucciones específicas;
- no quieres explicar el contexto desde cero;
- estás desarrollando un proceso repetible.

### Un error habitual

En lugar de crear un único chat gigantesco con estrategia, diseño, proveedores, presupuesto, correos, contratos y calendario, conviene usar:

```text
Un Project
├── Chat 1: Estrategia
├── Chat 2: Presupuesto
├── Chat 3: Proveedores
├── Chat 4: Marketing
└── Chat 5: Riesgos
```

Así compartes el contexto general, pero mantienes cada conversación enfocada.

## 9. Projects y memoria

Projects y memoria se relacionan, pero no son idénticos.

### Memoria general

Puede ayudar a recordar preferencias útiles para futuras conversaciones:

- prefieres respuestas en español;
- estás aprendiendo programación;
- diriges una empresa;
- quieres explicaciones para principiantes.

### Contexto del Project

Se centra en una iniciativa:

- sus archivos;
- sus instrucciones;
- sus conversaciones;
- sus objetivos.

La pregunta correcta es:

> «¿Esta información debería utilizarse en muchas conversaciones o solamente dentro de este proyecto?».

**Memoria general:**

> «Prefiero explicaciones simples y estructuradas».

**Instrucción de Project:**

> «En este proyecto, todas las propuestas deben dirigirse al mercado británico y utilizar la voz de marca definida en `brand-guide.pdf`».

Según las opciones disponibles, un proyecto puede usar un contexto más aislado. La configuración exacta puede depender del plan, de cuándo se creó y de las políticas del espacio de trabajo.

---

## 10. Projects no significa almacenamiento local

Un Project de ChatGPT es principalmente una entidad asociada a tu cuenta en la nube. Aunque accedas desde la aplicación de escritorio, sus chats, archivos e instrucciones suelen formar parte del entorno sincronizado.

Por tanto:

> Un Project no es una carpeta de Windows o macOS.

Puedes tener:

```text
Project de ChatGPT:
«Página web de mi empresa»
```

y también:

```text
Carpeta local:
C:\Users\Ana\Documents\empresa-web
```

Pueden estar relacionadas, pero no son lo mismo. Codex o Work local pueden trabajar con la carpeta local; el Project mantiene el contexto organizativo.

## 11. Qué son Scheduled Tasks

Una **Scheduled Task** permite pedirle a ChatGPT que haga algo más adelante. Puede ser:

1. una tarea única;
2. una tarea recurrente;
3. una comprobación periódica;
4. una vigilancia de una condición.

### Ejemplos

**Recordatorio único:**

> «Recuérdame enviar el informe mañana a las 9:00».

**Tarea recurrente:**

> «Cada lunes por la mañana, prepara un resumen de las noticias de inteligencia artificial».

**Monitorización:**

> «Avísame cuando cambie el precio de este producto».

**Revisión periódica:**

> «Cada viernes, revisa mis próximos eventos y crea una lista de preparación».

### Lo importante: se ejecutan en cloud

Una Scheduled Task debe poder ejecutarse aunque no tengas abierto el chat o no estés delante del ordenador. Por eso su funcionamiento principal es cloud.

No es lo mismo que el Programador de tareas de Windows o `cron` en Linux y no puede ejecutar libremente cualquier programa local.

---

## 12. Scheduled Tasks frente a automatizaciones de Codex

Son conceptos similares, pero con objetivos diferentes.

### Scheduled Tasks de ChatGPT

Se orientan a:

- recordatorios;
- resúmenes;
- comprobaciones;
- informes recurrentes;
- vigilancia de novedades;
- actividades personales o de conocimiento.

### Automatizaciones de Codex

Se orientan a flujos técnicos:

- revisar un repositorio;
- ejecutar procesos de desarrollo;
- comprobar tests;
- hacer revisiones técnicas;
- automatizar tareas de código.

---

## 13. Limitaciones importantes de Scheduled Tasks

### Acceso a archivos de un Project

No debes asumir que una tarea creada dentro de un Project podrá leer automáticamente todos sus archivos durante cada ejecución.

### El chat asociado importa

Una tarea puede quedar asociada a una conversación. Si se elimina esa conversación, la tarea puede pausarse. Eliminar la tarea no necesariamente elimina la conversación.

### Límites de tareas activas

La cantidad disponible depende del plan y de las políticas de la cuenta.

### Compatibilidad de herramientas

No todas las experiencias y herramientas de ChatGPT tienen que ser compatibles con las tareas programadas. La disponibilidad puede cambiar con el producto y el plan.

## 14. Cómo se combinan todas las piezas

### Caso A: aprender un tema

```text
Project: Aprender inteligencia artificial
├── Archivos: apuntes y libros
├── Instrucciones: explicar para principiante
├── Chat: preguntas diarias
├── Work: crear una guía de estudio
└── Scheduled Task: enviar un ejercicio cada mañana
```

- Project organiza.
- Chat enseña.
- Work produce la guía.
- Scheduled Task mantiene el hábito.
- El conjunto puede funcionar principalmente en cloud.

### Caso B: analizar una empresa

```text
Project: Análisis empresa X
├── Archivos financieros
├── Chats de investigación
├── Work para crear el informe
└── Scheduled Task para vigilar nuevas noticias
```

Work investiga y crea el entregable. La tarea programada puede vigilar cambios públicos, pero no debes asumir que leerá automáticamente todos los archivos del Project.

### Caso C: desarrollar software

```text
Project de ChatGPT: Nueva aplicación
├── Requisitos
├── Investigación
├── Decisiones de producto
└── Chats de diseño

Carpeta local:
~/repos/nueva-aplicacion

Codex local:
- modifica el repositorio
- ejecuta tests
- revisa errores

Codex remoto o cloud, cuando está disponible:
- trabaja remotamente sobre tareas delegadas
```

El Project conserva el contexto conceptual; Codex trabaja sobre el código.

### Caso D: crear una presentación desde archivos locales

```text
Work local
├── Abre documentos autorizados
├── Analiza hojas de cálculo
├── Crea una presentación
└── Guarda el archivo en tu ordenador
```

Esto es distinto de subir manualmente cada archivo a un chat cloud.

## 15. Subir archivos o dar acceso local

### Subir un archivo

1. Seleccionas una copia concreta.
2. Esa copia se incorpora a la conversación o Project.
3. ChatGPT trabaja con la versión subida.
4. Los cambios posteriores en tu archivo local no se reflejan automáticamente.

Si subes `presupuesto.xlsx` el lunes y modificas el original el martes, la copia subida no necesariamente se actualiza.

### Acceso local

Cuando un agente trabaja directamente con un archivo autorizado, por ejemplo:

```text
C:\Empresa\presupuesto.xlsx
```

puede abrir la versión actual y, según el flujo y los permisos, modificarla directamente. Esto ofrece más capacidad, pero también más riesgo.

---

## 16. Aplicaciones conectadas frente a acceso local

Una aplicación conectada, como correo o calendario, no equivale a acceso general a tu PC.

### Aplicación conectada

ChatGPT utiliza una integración autorizada para acceder a información específica:

- correos;
- eventos;
- contactos;
- documentos de un servicio;
- información empresarial.

El acceso está limitado por los permisos de la aplicación, las capacidades de la integración, las políticas de la cuenta y los controles del administrador.

### Acceso local

El agente interactúa con recursos del ordenador mediante la aplicación de escritorio, la terminal u otras herramientas locales.

```text
Gmail conectado ≠ acceso a todo tu navegador
Google Calendar conectado ≠ acceso a todo tu ordenador
Carpeta local autorizada ≠ acceso a todo tu disco
```

## 17. Historial y sincronización

| Tipo | Sincronización típica |
|---|---|
| Chat cloud | Sí |
| Work cloud | Sí |
| Work local | Puede permanecer en el ordenador |
| Codex | Historial o vista separados |
| Project | Asociado a la cuenta y sincronizado |
| Scheduled Task | Administrada desde la cuenta |

La sincronización y disponibilidad exactas pueden depender del producto, el plan, el dispositivo y las políticas del espacio de trabajo.

## 18. Privacidad y entrenamiento

Hay tres preguntas diferentes que no deben mezclarse:

1. **¿Dónde se ejecuta el trabajo?**
2. **¿Dónde se guarda el historial?**
3. **¿Puede utilizarse el contenido para mejorar los modelos?**

No son la misma cosa.

### Controles de datos

En cuentas personales existen controles de datos para administrar si las nuevas conversaciones pueden utilizarse para mejorar modelos. Esos controles pueden aplicarse a la cuenta y sincronizarse entre dispositivos.

### Temporary Chat

Los chats temporales están diseñados para no aparecer en el historial ni crear memoria. OpenAI puede conservar datos durante un periodo limitado por motivos de seguridad, conforme a sus políticas vigentes.

### Codex

Codex puede tener controles específicos relacionados con sus entornos y flujos. Conviene revisar tanto la configuración general de ChatGPT como la configuración propia de Codex.

### Cuentas empresariales

Las cuentas Business, Enterprise, Edu y los servicios de API pueden estar sujetas a compromisos y políticas de datos diferentes de las cuentas personales. También pueden existir controles administrados por la organización.

> Como estas políticas pueden cambiar, revisa siempre la documentación y la configuración actuales antes de trabajar con información sensible.

## 19. Cómo pensar en los permisos

### Permiso para leer

> «Puedes abrir estos archivos».

### Permiso para escribir

> «Puedes modificar estos archivos».

### Permiso para ejecutar

> «Puedes ejecutar comandos».

### Permiso de red

> «Puedes conectarte a internet o a determinados dominios».

### Permiso para aplicaciones

> «Puedes utilizar Gmail, Calendar, Drive u otra aplicación conectada».

### Permiso para acciones externas

> «Puedes enviar, publicar, borrar, comprar o modificar algo fuera del entorno de análisis».

Una regla mental útil:

> Leer suele ser menos arriesgado que escribir. Escribir suele ser menos arriesgado que ejecutar. Actuar sobre sistemas externos requiere una atención especial.

## 20. Qué elegir en cada situación

### Utiliza Chat cuando…

- quieres una explicación;
- tienes una pregunta concreta;
- quieres conversar;
- quieres revisar una idea;
- necesitas un texto rápido;
- quieres interpretar un documento;
- el trabajo puede resolverse interactivamente.

### Utiliza Work cuando…

- tienes un resultado final claro;
- necesitas varios pasos;
- hay múltiples archivos;
- quieres un documento, hoja, presentación o informe terminado;
- necesitas una investigación extensa;
- esperas que el agente organice y ejecute el proceso.

### Utiliza Codex cuando…

- el resultado principal es código;
- hay un repositorio;
- necesitas ejecutar tests;
- necesitas una terminal;
- quieres modificar archivos de software;
- necesitas depurar, revisar o implementar.

### Utiliza un Project cuando…

- el tema durará más de una sesión;
- existen varios documentos;
- quieres separar conversaciones;
- necesitas instrucciones persistentes;
- quieres compartir contexto entre chats del mismo esfuerzo.

### Utiliza Scheduled Tasks cuando…

- algo debe ocurrir después;
- debe repetirse;
- quieres una notificación;
- quieres comprobar periódicamente una condición;
- quieres un informe recurrente.

## 21. Árbol de decisión sencillo

```text
¿Solamente necesitas una respuesta o conversación?
│
├── Sí → Chat
│
└── No
    │
    ├── ¿El resultado principal es software o código?
    │   │
    │   ├── Sí → Codex
    │   │
    │   └── No → Work
    │
    └── ¿Este trabajo continuará durante días o semanas?
        │
        ├── Sí → Colócalo dentro de un Project
        └── No → Puede ser una sesión independiente

¿Debe ejecutarse más adelante o repetirse?
│
├── Sí → Scheduled Task
└── No → Ejecución normal

¿Necesita tocar archivos o programas de tu PC?
│
├── Sí → Flujo local con permisos
└── No → Cloud suele ser suficiente
```

## 22. Errores conceptuales frecuentes

### Error 1: «Work es una carpeta»

No. Work es un agente o modalidad de trabajo. Project es el contenedor.

### Error 2: «Codex es solo otro modelo de chat»

Es más útil entenderlo como un agente y conjunto de interfaces especializadas en programación.

### Error 3: «Local significa que nada sale de mi ordenador»

No necesariamente. El agente puede ejecutar herramientas localmente mientras consulta un modelo remoto.

### Error 4: «Cloud puede ver automáticamente todo mi PC»

No. Necesita que subas archivos, conectes aplicaciones o autorices herramientas.

### Error 5: «Un Project trabaja por sí solo»

No. Organiza contexto. Chat, Work u otras herramientas realizan el trabajo.

### Error 6: «Scheduled Tasks puede ejecutar cualquier programa local»

No. Es una automatización cloud de ChatGPT, no un reemplazo general del programador de tareas del sistema operativo.

### Error 7: «Si la tarea está en un Project, tiene todos sus archivos»

No debes asumirlo. El acceso depende de las capacidades vigentes de Scheduled Tasks.

### Error 8: «Memoria y Project son lo mismo»

No. La memoria personaliza la experiencia general; el Project agrupa contexto para una iniciativa.

## 23. Curva de aprendizaje recomendada

### Nivel 1: dominar Chat

Aprende a:

- hacer preguntas concretas;
- proporcionar contexto;
- pedir ejemplos;
- corregir el resultado;
- pedir explicaciones resumidas;
- adjuntar un archivo;
- buscar información actualizada.

**Objetivo:** usar ChatGPT como tutor y asesor.

### Nivel 2: aprender Projects

Crea un Project llamado:

```text
Aprender ChatGPT
```

Añade instrucciones:

```text
Explícame todo como a un principiante.
Usa ejemplos concretos.
Define cualquier término técnico.
Organiza la información de menor a mayor dificultad.
```

Crea chats separados para Fundamentos, Prompts, Projects, Privacidad, Codex y Automatización.

**Objetivo:** mantener contexto sin crear conversaciones inmanejables.

### Nivel 3: aprender Work

Prueba este encargo:

> «Usa mis apuntes para crear una guía de estudio organizada en cinco módulos, con ejercicios y un glosario».

**Objetivo:** pasar de pedir respuestas a delegar entregables.

### Nivel 4: aprender Scheduled Tasks

Empieza con algo sin riesgo:

> «Cada lunes por la mañana, recuérdame revisar mis objetivos de la semana».

Después prueba:

> «Cada viernes, prepara un resumen de las principales novedades sobre ChatGPT».

**Objetivo:** entender la diferencia entre conversar ahora y ejecutar después.

### Nivel 5: aprender Codex en un repositorio de prueba

Usa una carpeta pequeña:

```text
hello-codex/
├── README.md
├── calculator.py
└── test_calculator.py
```

Pídele que explique el código, añada una función, ejecute tests y muestre los cambios.

**Objetivo:** entender lectura, escritura, ejecución y revisión.

### Nivel 6: combinar local y cloud

Prueba el mismo tipo de tarea en ambos entornos y observa:

- qué versión del archivo ve;
- dónde aparece el historial;
- dónde se guarda el resultado;
- qué permisos solicita;
- si puede continuar con tu ordenador apagado.

## 24. Flujo recomendado para trabajar con seguridad

Antes de delegar una tarea, define:

### 1. Objetivo

```text
Crear un informe de ventas del segundo trimestre.
```

### 2. Fuentes permitidas

```text
ventas.xlsx
clientes.csv
notas-reunion.docx
```

### 3. Acciones permitidas

```text
Leer archivos.
Crear un informe.
No modificar los originales.
```

### 4. Lugar de salida

```text
Guardar el resultado como informe-ventas-q2.docx.
```

### 5. Restricciones

```text
No enviar correos.
No publicar.
No eliminar archivos.
No utilizar datos fuera de la carpeta.
```

### 6. Revisión

```text
Mostrar un resumen de los cambios y pedir aprobación antes de cualquier acción externa.
```

Este formato funciona especialmente bien con Work y Codex.

## 25. Ejemplos completos de instrucciones

### Para Work

```text
Analiza los archivos de esta carpeta relacionados con las ventas del segundo
trimestre.

Objetivo:
Crear un informe ejecutivo para dirección.

Debes:
- revisar las hojas de cálculo;
- identificar tendencias;
- señalar anomalías;
- crear tres gráficos;
- escribir conclusiones y recomendaciones;
- producir un documento Word terminado.

Restricciones:
- no modifiques los archivos originales;
- no envíes el informe;
- no utilices archivos fuera de la carpeta autorizada;
- indica cualquier dato que no puedas verificar.
```

### Para Codex

```text
Revisa este repositorio y determina por qué fallan los tests de autenticación.

Debes:
- reproducir el fallo;
- identificar la causa raíz;
- proponer un plan;
- modificar solamente los archivos necesarios;
- ejecutar los tests;
- mostrar el diff final;
- no hacer commit ni push;
- no cambiar dependencias sin explicarlo.
```

La calidad del resultado mejora cuando separas:

- objetivo;
- alcance;
- permisos;
- restricciones;
- formato de salida;
- criterio de éxito.

## 26. Resumen definitivo

### Chat

Conversación y ayuda rápida.

```text
«Explícame, ayúdame a pensar, responde, compara».
```

### Work

Agente general para trabajos complejos y entregables.

```text
«Investiga, analiza, crea y entrégame el resultado».
```

### Codex

Agente especializado en software.

```text
«Abre el repositorio, modifica el código, ejecuta tests y revisa cambios».
```

### Projects

Contenedor persistente de contexto.

```text
«Guarda juntos los chats, archivos e instrucciones de esta iniciativa».
```

### Scheduled Tasks

Ejecución futura, recurrente o condicional.

```text
«Haz esto mañana, cada semana o cuando ocurra un cambio».
```

### Local

Acceso autorizado a recursos de tu ordenador.

```text
«Trabaja con mis carpetas, archivos, aplicaciones o terminal».
```

### Cloud

Ejecución en infraestructura remota.

```text
«Trabaja en servidores remotos y sincroniza el resultado».
```

### Relación entre todos los conceptos

```text
                         CHATGPT
                            │
          ┌─────────────────┼──────────────────┐
          │                 │                  │
        Chat              Work              Codex
   conversación      trabajo general       programación
          │                 │                  │
          └────────────┬────┴──────────┬───────┘
                       │               │
                    Projects      Scheduled Tasks
                    contexto       ejecución futura
                       │               │
                       └───────┬───────┘
                               │
                     Local o Cloud
                  según recursos y entorno
```

> **Chat conversa. Work produce. Codex programa. Projects organiza. Scheduled Tasks automatiza. Local toca tu ordenador; cloud trabaja en servidores remotos.**
